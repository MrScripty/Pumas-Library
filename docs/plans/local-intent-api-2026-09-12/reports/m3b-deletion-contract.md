# M3b deletion and relocation contract

Status: admitted design record. Historical source observations below preceded implementation; current behavior and verification are recorded in [the M3b implementation report](m3b-local-desired-state.md).

## One destructive-operation protocol

Use the existing native root exclusion in `DownloadDestinationRoot::try_acquire_execution_grant`, together with the M3a SQLite deletion claim. These serve different purposes: the native grant excludes download filesystem effects/admission while the durable claim excludes retention and survives process death. Do not create another downloader, scheduler, or library owner.

1. Validate every affected canonical model ID and prepare the operation without changing files. Resolve source/destination through the existing held root capability, rejecting substituted roots and symlink traversal.
2. Register the full operation with the existing runtime effect owner (the M3b extension of RuntimeTasks), before starting an effect. The owned inner future receives cloned ModelLibrary and owned inputs; caller awaits a result channel. Dropping the caller must not abort that inner future. All blocking joins stay inside it.
3. Acquire native root grants nonblocking. For a cross-library move, acquire roots in stable physical-root order and coalesce identical roots. Busy means a typed conflict; do not wait while holding a SQLite transaction.
4. Under the grants, use the existing strict download lifecycle inventory to reject unresolved custody for every affected source or destination. Include hidden admissions and dormant/paused/failed rows; a public task snapshot or an empty live queue is insufficient. Errors are conflicts/errors, never empty inventory. Reuse the recovery destination identity comparison, not untrusted persisted display paths.
5. Acquire durable claims for every affected ID, in stable order, using fresh tokens. Retained and preexisting claims reject the operation. A claim for a destination also excludes an ensure for a currently missing local model. If acquiring later claims fails before effects, explicitly settle already acquired tokens; no destructor releases claims. Across separate databases the native grants make ordered acquisitions safe; SQLite transactions are short.
6. Revalidate operation preconditions while protected, then perform the existing link/index/filesystem changes. Claims and grants remain owned until every async filesystem operation and blocking task result has been observed.
7. After a fully observed successful operation, explicitly release exact claim tokens before dropping grants. If no mutation started and preflight failed, explicit release is safe. After partial mutation, join panic, cancellation of the effect owner, ambiguous commit, or failed settlement, preserve remaining claims and report failure. Never release in Drop. A process crash leaves claims blocking.

Startup reports unresolved claims and prevents affected ensure/bind/destructive operations. It does not expire them or infer completion from missing catalog rows/directories. M3a claims do not encode operation kind, destination, or progress, so automatically completing an interrupted relocation from them is unsupported. Explicit recovery needs evidence; ordinary startup must preserve custody.

## Required effect-owner seam

Direct ModelLibrary entrypoints need the same caller-drop safety as API entrypoints. Putting a guard only in PumasApi is insufficient. Reuse the M3b RuntimeTasks ownership implementation at a layer accessible to ModelLibrary and share its handle through composition/clones. If moving that utility to a common module is necessary, retain one implementation and one owner instance per composed library. Do not spawn an untracked destructive task and call it orderly shutdown. The owner closes admission, drains these effects, and only then permits HF shutdown. Standalone ModelLibrary construction needs the same ownership utility, without creating an HF client.

Synchronous `cleanup_duplicate_repo_entries` can hold claims/grants directly for its synchronous effects; if invoked via spawn_blocking, its owning async wrapper must retain the join. API shutdown must not abort the wrapper and report a drained library.

## Download custody integration is a concrete prerequisite

ModelLibrary currently has no DownloadPersistence handle or configured download-store directory. Source libraries opened by LibraryMerger have the same gap. Do not guess the store directory or call DownloadPersistence::load_all (which can hide errors).

Composition must supply a narrow existing download-authority handle/callback that checks `load_lifecycle_inventory_strict` against held destination identities while the root grant is held. The capability must cover the root's configured store, including source roots used by merge. If custody cannot be established for a destructive source, fail closed and preserve it; do not treat absence of an injected HF client as proof that no dormant download exists. An explicitly configured local-only authority may establish no managed download domain; this must be a composition decision, not inferred from an empty process map.

HF ambient admission already inherits a protected root grant near `hf/download.rs`'s "durably admit download" block. Managed admission, restore/resume, and final mutation/import must also check persisted deletion claims for the managed model ID while holding that same root exclusion. This stops a new admission during a claim, including after a crashed deletion released its native OS lock. Do not block the downloader's own import merely because an intent declaration retains its output; only an active deletion claim blocks it. Checks outside the native grant leave a check/admit race.

## Exact operation scopes

| Entry point | Guard scope and behavior |
| --- | --- |
| `ModelLibrary::delete_model` | Claim before the first index/link removal. A retained model returns typed conflict regardless of cascade. Deleting an external reference removes only the registry artifact, preserving existing external-target semantics. Keep the claim through parent cleanup and observed link operations. |
| `reclassify_model` | Pure metadata changes that keep canonical ID do not require relocation claims. Before rename, claim both old and new IDs, reject retention on either, and hold through metadata publication and index changes. Do not rewrite declarations to a guessed replacement ID. Revalidate destination absence under protection. |
| `reclassify_all_models` | Delegates to guarded per-model operation and reports conflicts using existing per-model error reporting. |
| `cleanup_duplicate_repo_entries` | Claim duplicate source before removing bytes. Partial-payload merge mutates both identities: claim preferred and duplicate before merging, and preserve both if either is retained/busy. A retained duplicate remains unresolved; no declaration deletion or replacement. Projection-only cleanup of already missing rows does not remove retention. |
| `LibraryMerger::merge_single_model` | Before move/copy, protect source and destination roots and claim both IDs through copy, source removal, and destination indexing. Reject retained source or destination; do not transfer declarations implicitly. Source and target may use distinct ModelIndex authorities. |
| API links/state deletion dispatch | Delegate to guarded ModelLibrary method; no second retention check that can race. |

LibraryMerger's current `cleanup_source` calls `remove_dir_all(source_path)` whenever the merge has no errors. This destroys skipped duplicate payloads and the source models.db, including unbound declarations or crash claims. Remove this recursive cleanup behavior in M3b. Only remove demonstrably empty payload parent directories, and preserve the source authoritative database/root. An empty payload scan is not permission to discard desired state. Also replace merge's destination-overwriting rename/copy behavior with an existing no-replace operation or fail safely on a late collision while under the protected roots.

## Sol implementation split and evidence

Library owner: shared guard helper, delete/reclassify/duplicate operations and typed retained/busy mapping. Merger owner: source authority plumbing, two-root/two-index protocol, no recursive source-root deletion. HF owner: claim checks under existing grants and strict custody callback; no new download inventory. Lifecycle owner: share and drain existing effect ownership down to direct library entrypoints.

Required tests use real files and independent SQLite connections: retained direct deletion/cascade and relocation preserve bytes; a claim wins against concurrent ensure before first destructive effect; caller dropped after delete starts cannot let ensure succeed while effects remain; partial failure retains claim on reopen; downloader busy and dormant/hidden custody refuse deletion; active crash claim blocks fresh download admission; retained duplicate blocks partial merging; merge retains skipped payloads and source declarations; no late destination overwrite. Inject synchronization at actual mutation/settlement boundaries rather than relying on sleeps. Public release only removes its declaration and never invokes these operations.

## Settled minimal composition recipe for implementation

Proposed compatibility decision for parent admission: `ModelLibrary::new` initializes destructive authority to Unknown. This preserves read/index/import construction, but a direct destructive call must return a typed authority-unavailable error before acquiring a claim or mutating anything until trusted composition installs its authority. This is a deliberate lower-level behavior change; do not describe existing standalone deletion/merge compatibility as unchanged.

Use a shared, install-once slot on ModelLibrary clones containing the existing runtime effect owner, held root capability, and the existing `Arc<DownloadPersistence>`. A concrete shape is `LibraryMutationAuthority { tasks: RuntimeTasks, root: DownloadDestinationRoot, downloads: Arc<DownloadPersistence> }`, behind `Arc<OnceLock<_>>`. A crate-private configuration method validates that the held root is this library's physical root and installs once before public destructive work. No mutable toggle may turn a composed library back into an unguarded/no-download mode. Test-only construction can install a known local-only authority for isolated temp roots; do not expose that assertion as a public safety bypass.

In `api/builder.rs`, move construction of its existing `DownloadPersistence` handle from inside the `enable_hf_client` branch to the configured primary composition scope. There remains exactly one handle for `launcher_root/launcher-data`, shared with both the library guard and HF if HF initializes. Configure the library with the already-created RuntimeTasks owner before scheduling reconciliation/public operations. If HF is disabled or client initialization fails, still inspect this configured store: an optional client says nothing about historical paused/download recovery custody. A strict valid missing store can establish empty inventory through the store's existing semantics. Malformed inventory remains a destructive-operation refusal. This is configuration supplied by the primary owner, not a guessed location in ModelLibrary.

The guard helper implementation is:

- `mutation_authority()` clones the configured handle or returns the typed unavailable error; it performs no filesystem/SQLite mutation.
- An owned async entrypoint clones that authority and library, then submits its inner future through `tasks` and awaits its result. All claim acquisition and effect execution live in the inner future.
- A synchronous protected helper acquires the held root's native grant, strictly checks lifecycle inventory for the validated affected destination identities, acquires the exact claim tokens, and returns explicit custody state to the inner operation. Claim state has no releasing Drop implementation.
- `finish_success()` releases exact tokens only after observed completion; `finish_unstarted()` releases exact tokens only when no destructive effect began. Other exit paths preserve claims. Native grants can drop on panic because claims remain authoritative and HF checks them before later effects.
- For root-only synchronous duplicate cleanup, use the same configured authority and custody helper synchronously; no nested async owner is needed for synchronous effects. The caller owning any blocking wrapper retains its join through shutdown.

For LibraryMerger, add a crate-private `merge_from_library(source: Arc<ModelLibrary>)` factoring the existing implementation; both source and destination must already have installed authority. Existing public path-only `merge(source_path)` can open its source for inspection but must reject before any destructive move because that constructor cannot establish source custody. The minimal M3b proposal intentionally does not invent a new public store-path argument. Report this path-only merge limitation explicitly. A future public composition API can admit an already configured source with a proper authority contract; internal tests exercise the crate-private seam now.

Before configuring, ModelLibrary startup does run byte-complete partial finalization and index reconstruction. This proposal does not authorize moving destructive duplicate cleanup ahead of configuration or using startup construction to bypass claims. Any startup step found to remove/rename model payloads must use the same configured seam or be deferred until composition; pure projection reconstruction leaves authoritative declarations/claims intact.

## Admitted HF capability seam

Parent admitted a narrow `download_recovery.rs` change: `DownloadRecoveryDestination::assert_no_intent_deletion_claim` validates its held root, opens an existing `models.db` through `ModelIndex::open_read_only`, observes strict authoritative claims, and revalidates root/database identity. It creates no database or schema. Only a genuinely absent database at a currently valid standalone download root is treated as having no prior intent store; malformed/unreadable/substituted databases fail closed. Read-only SQLite uses the existing bounded connection behavior; no new indefinite wait is introduced. HF invokes this observation under the existing root grant before admission, resume, worker effects, recovery admission, and cancellation cleanup. Domain refusal is returned as an observed inner result, preserving lifecycle shutdown semantics.

The admitted `DownloadInvocationContext::held_root_execution_grant` accessor clones the existing Arc grant into nested owned preparation. The library's under-grant preparation method validates that proof against its installed authority and must not reacquire the same native lock.

## Destructive capability implementation amendment

Parent admitted held-directory mutation helpers in `download_recovery.rs`: recursive unlink of a bound model directory, metadata-only reading, metadata publication through the existing capability-aware AtomicJsonTarget, and Linux `renameat2(RENAME_NOREPLACE)` with held parent descriptors. The rename supports distinct configured roots on the same filesystem when the caller holds both root grants and claims. It never falls back to ambient-path copying: cross-filesystem relocation is refused with source bytes preserved. Unsupported platforms likewise refuse capability relocation. Destructive operation callers retain claims after ambiguous mutation or publication outcomes.

Payload symlinks are unlinked during deletion, never recursively followed. Capability tests cover substituted model/root/target-parent preservation, metadata substitution refusal, real cross-root rename, and no overwrite. These are targeted evidence, not a claim that arbitrary external processes cannot rename a directory they already own while Pumas holds it.

M3b deliberately preserves incomplete duplicate groups requiring partial-file transfer; it reports them unresolved instead of invoking the existing ambient-path merge. Removing exact duplicate directories can use held recursive deletion. Optional raw-path empty-parent pruning is omitted from guarded effects unless backed by held-parent authority. This leaves empty ancestors and preserves correctness. Public path-only LibraryMerger refuses unconfigured source authority before constructing/migrating a source ModelLibrary; the internally composed-source path can use guarded same-filesystem rename. Standalone lower destructive operations require explicit trusted internal composition, as admitted above.

## Additional migration bypass found during integration review

Constructor startup does not execute the explicit metadata migration runner. It does invoke `auto_finalize_complete_partial_artifacts_on_startup`, which can promote `.part` files through raw paths before trusted mutation authority exists. Defer/remove that constructor mutation: configured HF restoration already owns immutable byte-complete inspection/promotion, while an unconfigured library must preserve unresolved bytes and deletion claims.

The explicit `library/migration.rs::execute_migration_with_checkpoint` is reachable through the public migration API and state dispatcher. Its ordinary planned move uses raw directory rename; split-directory work renames individual files/marker and removes source metadata. These are retention bypasses absent from the earlier inventory and require the same owned claims/capabilities. Normal moves can reuse held rename/metadata publication; split transfer must refuse before effects until a bounded held-file transfer protocol exists. Removing old raw empty-parent cleanup helpers must also remove their migration wrapper/callers, rather than restore unsafe ambient pruning to satisfy compilation. Parent coordinates this additional narrow migration amendment and its compatibility/evidence gates.

## Interrupted desired acquisition recovery correction

A fresh HF owner projects persisted Queued/Downloading entries as live Paused, so treating every live Paused observation as an explicit operator pause prevented durable desired-state repair after a real crash. The admitted `resume_interrupted_download(id, expected_ref)` uses the existing owned resume path, retaining the same exact admission and destination queue position. It requires an immutable expected model/artifact reference, live managed Paused without failure/cancellation/pause evidence, and a strict current persisted Queued/Downloading snapshot matching request, revision, files, destination and confirmed admission attempt. Persisted Paused, Pausing, Error and unresolved custody are not automatic repair authority.

Desired orchestration holds its shared declaration gate, rereads exact generation and bound target, then invokes this restricted helper. It never calls the public operator resume method for reconciliation. The final existing worker installation rechecks live identity and the pause flag. An explicit user pause on a restored dormant active entry sets that flag before asynchronous persistence and durably writes Paused, preventing an already-inspected automatic resume from overriding the user. This introduces no new writer, queue, store or scheduler.
