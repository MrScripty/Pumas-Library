## Smallest complete API and declared universe

`CatalogRequest::from_observed` accepts the trusted caller's original selection
identity, stable release/build, root requirements/constraints, exact direct
roots and finite complete provider observations. The target comes from private
`ProducedTorchTarget`, not an imported resolution/approval document. The request
digest covers original requirements, complete raw observations, repository/
project URLs, times and full target binding. No global 2.9.1 pin or NetworkConfig
registry is introduced.

This implements the design's **finite immutable provider-catalog option**.
The trusted caller supplies full Simple JSON API 1.0–1.3 project bodies or empty
observed 404 absence. There is no live metadata fetcher, HTML adapter or implicit
fetch when a new dependency appears. Duplicate fields, pagination/unknown
protocol, failed responses or missing reachable project/repository coverage
cannot establish completion. Existing selected-build PyTorch and PyPI authority
is fixed; both must cover each reachable name. Metadata URLs, redirects and
tracking hints cannot add repositories. Payload receiving rules include the
existing selected-build Torch/torchvision and macOS CPU exception.

Compatible filename tags and original explicit constraints admit candidates;
all admitted rows in the supplied finite catalog are acquired and inspected,
including rows that may prove unreachable. This conservative universe is not a
minimal solver closure or all upstream/current/future versions. No first-N,
newest-K or version selection occurs. Non-wheel rows are recorded exclusions and
never fetched. Candidate identity includes repository, original URL/hash/size
and policy data; `<artifact-id>/<filename>` avoids collisions between distinct
same-name/version/filename wheels. Original direct-root URL/hash/size remains
mandatory. Rust independently checks original row/source identity and receiving
grants before payload acquisition, alongside original request/target fences.

`CatalogContext::acquire` uses shared `acquire_http`, expected SHA256/size, one
attempt, no redirects and no ambient proxy. Unit-build-only anonymous loopback
mapping preserves HTTPS manifest identity; production has no plaintext fixture
option. The reserved directory's physical root must match the owning versions
root. The actual selected `-I` interpreter inspects held inputs under existing
managed child/stage/use custody. No payload downloader, build hook or solver is
added to Python.

Inspection checks actual hashes/size, exact namespaces, safe bounded ZIP members,
METADATA and WHEEL identity/tags. Actual Requires-Python determines eligibility;
contradictory optional index hints refuse. All actual Requires-Dist URLs refuse,
including inactive markers. A monotone fixed point unions alternative candidate
ranges and extras, revisits late extras, evaluates the full target and terminates
cycles under budgets. Empty domains remain evidence, never an incompatibility/
fallback signal. Yanked reasons/prereleases are retained without choosing policy.

Only the executed owned pipeline constructs `CompleteCatalog`, after final held
file/selected-executable/original-producer fences and shared receipt settlement.
It has no deserializer/import constructor. It retains raw request/observations,
target, stage and directory grant; the receipt is a `runtime.torch.catalog`
snapshot, not installation. It exposes no stale Using reopen/reuse API. The
private cold opener refuses unsettled records; production composition must use
that admission before activation. JSON receipts cannot renew selection authority
or mint Complete. Blocking work retains stage custody on abandonment; expected
validation refusal is outcome data inside the supervised effect.

## Bounds and measured evidence

Engineering refusal limits: 32 projects; 64 observations; 1 MiB/response and
8 MiB aggregate responses; 4096 rows/dependency fields/edges; 128 candidates;
128 ZIP members/wheel; 8 MiB expanded/wheel and 64 MiB aggregate; 1 MiB METADATA/
wheel and 8 MiB aggregate; 64 KiB WHEEL; 64 MiB aggregate expected/successfully
verified payload bytes; 10 MiB serialized request; 2 MiB plan/evidence; 120-second
operation deadline. Unknown size or an empty total acquisition set is Incomplete;
there is no invented unknown-body cap or metadata-only shared receipt. Limits
refuse rather than narrow the universe or authorize fallback.

These bounds qualify inert fixtures, not real provider/Torch volume. One attempt
and denied redirects remove repeated-success transfers. Shared acquisition checks
each expected representation size before excess writes; changed/oversized
responses cannot complete. This is **not** a hard raw socket/header/read-ahead
ceiling on failed transfers. Live metadata/retries/redirects/reacquisition and
raw-wire accounting need separate qualification; generic transport is unchanged.
